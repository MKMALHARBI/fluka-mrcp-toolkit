# Update 2026-11-05: mesh preparation at unpack

## Problem

Flair's mesh check (`SolidMesh::check4Overlaps`, run unconditionally when a
UMESH is loaded) tests whether the mesh frame's origin lies inside any
tetrahedron. Every ICRP mesh phantom encloses its own origin, so Flair
reported "Location [0, 0, 0] overlap found" for all phantoms. The UMESH
WHAT(1-3) translation does not help: the check runs in the local frame.
MRCP-10M also contains one inverted sliver tetrahedron (id 4258878, organ
5300, volume -2.86e-10 cm3), which Flair reports as an inverted element with
neighbour-link errors.

## Fix

`setup_data.py` now prepares each phantom once, right after unpacking:

- node coordinates are shifted by `MESH_OFFSET = (0, 0, 100)` cm
  (defined in `make_umesh.py`) so the origin is outside the body;
- tetrahedra of zero or negative signed volume are removed and the element
  ids renumbered from the file's base;
- the `.lung` airway file is shifted by the same offset;
- the ICRP originals are kept untouched next to the prepared files as
  `.node.icrp`, `.ele.icrp`, `.lung.icrp`;
- a marker comment line at the top of each prepared file records what was
  done, and makes the step idempotent.

Organ masses are unchanged (selftest: 11 passed, 0 failed, 1 skipped).

## Files changed

| file | change |
|------|--------|
| `setup_data.py` | `NODE_MARK`, `ELE_MARK`, `_marked()`, `repair()`, `repair_airway()`; both called from `setup()` for every present phantom |
| `make_umesh.py` | `MESH_OFFSET` constant; docstring |
| `make_examples.py` | BEAMPOS shifted by `MESH_OFFSET` |
| `voxelise.py` | nodes shifted back by `MESH_OFFSET` before voxelising |
| `slicer.py` | airway positions shifted back by `MESH_OFFSET` |
| `README.md` | "Mesh files" paragraph documents the preparation |

## Result

Toolkit 05M benchmark input: 0 errors, 0 warnings in Flair 3.4-5.4.
FLUKA 4-5.2 runs unchanged apart from the 100 cm z offset of the phantom.
